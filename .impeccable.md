## Design Context

### Users
Small closed group of friends (not a public consumer app) — young, urban, financially engaged users who connect real bank/credit/investment accounts via Plaid and want a fast, glanceable way to track spending, budgets, and shared-expense reimbursements. Used in short, frequent sessions (checking balances, categorizing a transaction, glancing at budget health) rather than long analytical sessions.

### Brand Personality
Premium, precise, quietly confident fintech — not playful, not corporate-cold. Numbers-first: financial amounts always carry the most visual weight on screen. Privacy-conscious by default (one-tap amount masking, secrets never shown in plaintext after entry). No strong external reference app — design.md's own spec (below) is the source of truth, not an imitation of an existing product.

### Aesthetic Direction
**Pivoted 2026-08 from dark-mode-first to light-mode-first**, per direct reference screenshots of 记账本 (the Chinese budgeting app `design.md` originally cited as a structural reference) — the user wants ToFi closer to that app's actual light aesthetic rather than the dark-fintech reinterpretation. Warm near-white background (never pure `#FFF`), white card surfaces lifted with soft shadow rather than border tints, and — the key visual shift — **category cards are fully-saturated pastel fills** (not a 10%-alpha tint on a dark card), each with a two-tone icon badge (a more-saturated inner circle behind the category-colored icon). Teal stays the singular brand accent (deepened to an AA-text-safe shade for light backgrounds), with the same semantic system underneath: emerald for income, rose for expense/over-budget, amber for approaching-budget, violet for reimbursements — each now has a "text-safe" deep variant for use as amount-text color against white, separate from the lighter/brighter variant used for icons and badge fills. The teal gradient HeroCard (net worth) carries over unchanged from the original dark-mode spec — it was already a self-contained tinted card, not dependent on the surrounding page theme. Typography (`DMSans_700Bold` / `Inter` / `JetBrainsMono`) and layout structure are unchanged; this is a color-token-level pivot, not a structural one.

### Design Principles
1. **Numbers first, always.** Largest type weight and visual priority goes to monetary amounts on every screen — never let decoration compete with a number for attention.
2. **Color encodes health, consistently.** Teal/amber/rose mean the same thing everywhere (cards, bars, badges, rings) — never repurpose these hues for anything else. On light backgrounds, use the deep/text-safe variant for amount text and the brighter/base variant for icons, badge fills, and card backgrounds — never the reverse (a bright base-shade used as small text on white will fail contrast).
3. **Follow docs/design.md literally, but design.md itself now reflects the light-mode pivot** — it was updated in lockstep with this file when the pivot happened. Exact hex values, type scale, spacing scale, and component layouts are specified there; implement as given rather than reinterpreting.
4. **Privacy is a first-class interaction**, not an afterthought — masking, secret-reveal-on-focus, and no-plaintext-after-save are functional requirements, not decoration.
5. **No AI-slop defaults.** No side-stripe borders, no gradient text, no glassmorphism, no generic rounded-card-with-shadow grids — the CategoryCard's pastel fill + two-tone icon badge and the mono-aligned TransactionRow are the distinctive signatures; lean into them rather than falling back to generic dashboard patterns.
6. **Semantic tokens only, never hardcoded hex in components.** Every screen/component uses `bg-background`, `text-textPrimary`, `bg-primary`, etc. — never a literal color. This is why the light-mode pivot was a token-value change in `constants/theme.ts`/`tailwind.config.js`, not a rewrite of every screen — keep it that way for any future retheme.
